SECTION 1: ARCHITECTURE ASSESSMENT
================================================================================

1.1 FRONTEND ARCHITECTURE
--------------------------
Current State:
- React 18 + Vite (SWC) + Tailwind CSS + shadcn/ui + Radix UI
- react-router-dom is installed but UNUSED — navigation is 100% state-driven
  via a `currentPage` string in App.jsx
- TanStack React Query is installed but not consistently used for data fetching
- All app code compiles into a single index.js chunk (~538KB, gzip: 151KB)
  with no route-based code splitting
- No URL-based routing means deep links, browser back/forward, bookmarks,
  and shared URLs are all broken
- framer-motion + Radix UI + all icon variants loaded eagerly

Critical Issues:
- No URL routing — cannot share a direct link to a specific page or feature
- Single fat bundle — slower initial load for all users
- No service worker / offline support
- No error boundary at route level — one component crash takes down the full app

Technical Debt:
- App.jsx contains renderCurrentPage() — a growing switch statement (God component)
- State management is prop-drilling + context — no structured server-state layer
- CSS split across platform-premium.css, index.css, and inline Tailwind


1.2 BACKEND ARCHITECTURE
-------------------------
Current State:
- Node.js 20 + Express 5 + Sequelize ORM + PostgreSQL
- 29 route files, 34 controllers, 67 Sequelize models
- 17 ensureXSchema.js DDL migration scripts run on every server startup
- PM2 cluster mode configured (ecosystem.config.js)
- Dockerfile exists — Alpine Node 20, multi-stage build, production-ready
- winston logging, AWS S3 SDK, StorageService abstraction in place

Critical Issues:
  Issue                                 File                     Impact
  -------                               ----                     ------
  Dev pool acquire:1800000ms (30 min)   db/config.js:40-44       Silent hangs
  database/index.js imports db/config   database/index.js        Wrong pool in prod
  No token revocation/blacklist         middleware/auth.js        Stolen JWT valid 7d
  No refresh token flow                 helpers/tokens.js         Re-login every 7d
  Synchronous OpenAI LLM calls          aiInterviewController.js  2-8s event loop block
  17 DDL scripts on every startup       database/ensure*Schema.js 200-500ms per restart
  contentSecurityPolicy: false          middleware/securityStack  Full XSS exposure
  No CI/CD pipeline                     (none)                    Manual broken deploys


1.3 DATABASE ARCHITECTURE
--------------------------
Current State:
- Single PostgreSQL database, shared schema multi-tenancy via tenant_id column
- PostgreSQL RLS middleware exists (middleware/tenantRls.js) but DISABLED by default
- 67 Sequelize models, schema evolution via ensureXSchema.js pattern
- No Sequelize migration files (no sequelize-cli migrations/ folder)
- No read replica, no connection pooler (PgBouncer)

Missing Indexes (High Certainty):

- (tenant_id, user_id) on connections, follows

Risks:

- No backup schedule documented; RDS PITR not yet configured

SECTION 5: DATABASE ROADMAP
================================================================================

Strategy: Stay on Shared PostgreSQL with tenant_id RLS for the pilot.
Migrate to Aurora PostgreSQL when approaching 50K users or 10+ tenants.


CRITICAL
---------

C1. Formal Migration System
  Replace ensureXSchema.js as primary evolution mechanism with sequelize-cli
  migrations. Keep ensureXSchema.js as safety net only.
  Migration naming: YYYYMMDDHHMMSS-description.js
  Benefits: ordered execution, rollback scripts, migration history table, CI enforcement.

C2. Add Missing Composite Indexes
  -- Feed (highest traffic)
  CREATE INDEX CONCURRENTLY idx_posts_tenant_created
    ON posts(tenant_id, created_at DESC);
  CREATE INDEX CONCURRENTLY idx_notifications_user_created
    ON notifications(user_id, created_at DESC);

  -- Network
  CREATE INDEX CONCURRENTLY idx_connections_tenant_user
    ON connections(tenant_id, user_id);
  CREATE INDEX CONCURRENTLY idx_follows_follower
    ON follows(follower_id, created_at DESC);

  -- Jobs
  CREATE INDEX CONCURRENTLY idx_jobs_tenant_status
    ON job_posts(tenant_id, status, created_at DESC);
  CREATE INDEX CONCURRENTLY idx_applications_user
    ON job_applications(applicant_id, created_at DESC);

  -- Messages
  CREATE INDEX CONCURRENTLY idx_messages_conversation
    ON messages(conversation_id, created_at DESC);

C3. Enable RLS Policies on All Tables
  ALTER TABLE posts ENABLE ROW LEVEL SECURITY;
  CREATE POLICY posts_tenant_isolation ON posts
    USING (tenant_id::text = current_setting('app.current_tenant_id', true)
      OR current_setting('app.bypass_rls', true) = 'true');
  Apply to all 67 tables.


HIGH PRIORITY
--------------

H1. Read Replica
  Add one RDS read replica. Route all SELECT queries in Sequelize to the replica.

H2. Connection Pooler (PgBouncer)
  With 3–6 ECS tasks × 20 connections = 60–120 connections to RDS.
  PgBouncer in transaction pooling mode reduces connection count by 80%.

H3. Automated Backups & PITR
  Enable RDS automated backups with 7-day retention.
  Enable Point-In-Time Recovery.
  Test restore quarterly.

H4. Query Performance Monitoring
  Enable pg_stat_statements.
  Connect AWS Performance Insights or pganalyze.
  CloudWatch alarm for queries > 1 second P95.

SECTION 7: DEVOPS & RELEASE STRATEGY
================================================================================

CI/CD Pipeline (Must build before launch)
-------------------------------------------
GitHub Actions workflow on push to main:
  1. Lint (ESLint frontend + backend)
  2. Unit tests (Vitest)
  3. Build Docker image → push to ECR
  4. Deploy to Staging (ECS rolling update)
  5. Run Playwright smoke tests against staging
  6. (Manual approval gate for production)
  7. Deploy to Production (ECS rolling update, 25% at a time)
  8. CloudWatch alarm check (5 min post-deploy)
  9. Slack/email notification


Environment Strategy:
  Environment    Trigger           Database               Purpose
  -----------    -------           --------               -------
  local          Developer machine Local Docker Postgres  Development
  staging        Push to main      RDS staging (separate) Integration testing
  production     Manual approval   RDS production         Live

  Never deploy directly to production without staging validation.


Feature Flag Strategy:
  Environment-based flags stored in tenant_settings JSONB and process.env.FEATURE_*:
    FEATURE_AI_INTERVIEW=true
    FEATURE_COMMUNITIES=true
    FEATURE_RESOURCE_LIBRARY=true
  Per-tenant flags override global flags.


Rollback Strategy:
  - ECS rolling deploy: always keep 1 previous task definition registered
  - Database: never run destructive migrations without a prior snapshot
  - Rollback command: aws ecs update-service --task-definition <previous-revision>
  - All migration files must have a down() rollback function


Monitoring & Alerting (CloudWatch Alarms):
  Metric                     Threshold              Action
  ------                     ---------              ------
  ALB 5xx Error Rate         > 1% for 5 min         PagerDuty + Slack
  ECS CPU Utilization        > 80% for 10 min       Scale out + alert
  RDS CPU                    > 70%                  Alert + investigate
  RDS Free Storage           < 10GB                 Alert
  RDS Connections            > 80% of max           Alert
  P95 API Latency            > 500ms                Alert
  Lambda Error Rate          > 5%                   Alert
  Redis Memory               > 80%                  Alert
